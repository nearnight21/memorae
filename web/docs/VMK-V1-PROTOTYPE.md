# VMK V1 原型边界

这个副本只复用原 `camp-memories` 项目，用来验证加密闭环。ThinkPad 主应用、线上数据库和线上图片不在测试范围内。

## V1 钥匙关系

```text
私密空间密码
  -> Argon2id 解锁钥匙
    -> 解开用户总钥匙 VMK
      -> 解开 TextKey
      -> 解开 PhotoKey
```

- `VMK` 不直接加密记忆或照片，只保护分类钥匙。
- `TextKey` 加密整条记忆 JSON，包括标题、正文、标签、日期和位置。
- 所有照片和缩略图共用一个 `PhotoKey`。
- 每次 AES-256-GCM 加密都生成独立的 12 字节随机 IV。
- 文件名、MIME 类型和文件长度作为加密元数据保存。
- 每份密文都绑定用途、记录 ID 和版本号，防止互换密文。

## 当前验证内容

- 创建并导出只含密文的钥匙信封。
- 换设备导入 JSON 后，用相同密码恢复 VMK。
- 加密和解密完整记忆对象。
- 加密和解密照片字节及照片元数据。
- 错误密码、篡改密文和锁定后继续访问均失败。
- 锁定时主动清零 JavaScript 可控的钥匙字节数组。
- 浏览器 IndexedDB 只保存钥匙信封、记忆密文和照片密文。
- 页面锁定后移除明文状态和解密照片 URL。
- 导出密文包、清空本设备、重新导入并输入密码，模拟换设备恢复。
- 用户选择的真实照片会先整体加密，再从密文解密后展示。

## 当前没有实现

- 不写入现有 Supabase `memories` 表，默认也不连接该项目。
- 不上传到现有 Cloudflare R2。
- 不迁移真实用户数据。
- 不实现恢复短语、系统安全区或生物识别。
- 不处理 RAW、视频及大文件分块。
- 不把当前数据格式视为最终生产格式；需要完成手机性能测试后再冻结参数。

自动测试使用较低的 Argon2id 内存参数来缩短测试时间；原型默认参数是 64 MiB、3 次迭代、并行度 1，之后仍需在目标手机上实测。
