# 前端现状汇报

> 检查范围：当前 Web 前端、浏览器实验、Figma 页面和交接文档。
>
> 本报告只做现状整理，不代表已经批准新的实现方案。

## 1. 网站现在长什么样

用户首先看到的是私密空间解锁入口。解锁后进入“足迹”产品。按现在的方向，Web 只有两种互相服务的形态：以地图为主的足迹主页，以及不带地图的简易版足迹回顾。

足迹地图是目前最重要的页面：

- 地图占据主要空间，使用高德地图。
- 记忆以照片圆标或聚合标记显示在地图上。
- 代码里还残留旧的左侧导航和模式切换，这是待改掉的旧结构，不代表最终产品方向。
- 地图上方主要保留地区等必要控制。
- 时间不再靠单独的顶部按钮或页面切换，而是依靠底部水晶时间轴控制。
- 右下角有新增记忆入口。

点击地图照片后，地图会继续保留，照片或记忆详情在地图上展开。用户可以继续看照片、文字、地点和日期，也可以进入图库或编辑状态。

目前重要状态包括：私密空间解锁、足迹地图总览、选中地区、展开记忆、简易版足迹回顾、照片图库、编辑记忆、地点导入、地图不可用和无匹配结果。

## 2. 哪些算正式设计

### 已经基本确定

- 足迹地图是 Web 的主要场景。
- 照片是地图上的主要内容。
- 地图作为主背景，控件浮在地图上。
- 点击照片后继续保留地图。
- Web 偏向大屏浏览，手机偏向采集和编辑。
- 地区和时间是重要的筛选维度。

这些方向在代码、Figma 和交接文档中都有重复依据。

### 还在尝试

- 水晶时间轴。
- 时间轴底部半隐藏、激活后展开的方式。
- 水晶材质的地区控件和新增按钮。
- 地图照片标记的最终样式。
- 地图详情、照片展开和图库之间的最终过渡。

这些已有原型或 Figma 画面，但还没有完全成为正式实现规范。

### 旧设计 / 可能淘汰

- 左侧固定主导航。
- 独立的“软木板”入口：软木板内容会并入足迹的附属回顾，不再单独存在。
- 独立的“普通时间线”入口：它会和软木板合并为简易版足迹回顾，不再与地图足迹平级。
- 地图顶部重复的时间筛选：时间统一由时间轴控制。
- 没有明确产品定义的“按时间与主题回顾”按钮。
- 旧版木质、深色、灯笼式界面。
- 旧版 TimelineControl 时间控制。

它们与现在“足迹为主场”的方向冲突，不应继续和新方案并列发展。

## 3. Figma 现在做了什么

### 已有页面

`10 Web / Footprints` 中已经设计了桌面足迹总览、选中地区、展开记忆、简易版足迹回顾、空结果、地图不可用、导入地点、地点确认和照片图库等状态。页面里仍有旧的“回顾”命名，但它应该理解为足迹下的附属回顾，不是独立主产品。

`02 Mobile` 中已经设计了移动端足迹、简易版足迹回顾、照片图库、编辑页和地图不可用等状态。移动端页面里仍有“时间线”旧命名，但产品上应归入简易版足迹回顾。

`00 Foundations + Components` 中有颜色、字体、间距、圆角，以及 PhotoMarker、RegionSelector、IconButton 和旧时间控制等基础组件。

### 已有组件

- PhotoMarker
- RegionSelector
- IconButton
- 旧版 TimelineControl（时间轴统一后应淘汰）
- Timeline / Crystal 水晶时间轴组件集

### 已被代码采用的部分

代码已经采用地图主场、地图照片标记、点击标记展开记忆、详情、图库、编辑和地点选择等大方向。

但网页不是按 Figma 逐像素实现的，更多是功能相近、具体外观不同。

### Figma 和网页不一样的地方

- Figma 新方案正在弱化或移除左侧栏，代码仍保留左侧栏。
- Figma 的方向 A 把足迹当主场，代码仍保留早期三模式切换逻辑。
- Figma 已有水晶时间轴组件，正式网页还没有接入它。
- Figma 多使用静态地图参考图，网页使用真实高德地图。
- Figma 页面状态很多，但代码路径和页面名称并不完全对应。

### Figma 表现不好的地方

Figma 可以做出水晶材质的静态近似，但不能真实表现地图图像被玻璃折射，也不能证明拖动、筛选、照片数量和地图标记会真正同步。

## 4. 浏览器里的设计实验

### 水晶时间轴实验

打开：`http://127.0.0.1:3000/?crystal-timeline=1`

它是在真实高德地图上测试水晶时间轴。支持鼠标、触摸和键盘操作，显示年份、当前时间焦点、拖动把手和日期浮层。

目前视觉和交互原型已经比较完整，但只在开发环境打开，没有正式接入足迹筛选和真实业务数据，也没有进入正式页面。

值得继续做，但下一步应该是确定正式尺寸、半隐藏状态，以及它和地图数据的连接，而不是继续堆玻璃效果。

### 开发密文验证工具

打开：`http://127.0.0.1:3000/?dev-vault=1`

它用于测试账号、密文、同步和本地数据，不是产品设计实验，正式构建不会显示。

### 旧软木板和旧的独立时间线入口

它们仍然存在于正式前端，更像上一阶段的页面拆分。内容不是全部丢弃，而是合并为足迹下面的简易回顾；不能继续作为两个独立入口。

## 5. 当前最大的设计混乱

- 左侧栏还是旧产品结构，但新方向已经不需要它。
- 代码还把软木板、时间线、足迹当成三个平级页面，但现在的方向只有“足迹地图”和“简易版足迹回顾”两种形态。
- Figma 新方向和网页现状没有完全对齐。
- 地图控件混有普通白色卡片、水晶玻璃和深色木质三套语言。
- 新增按钮同时存在金色版本和水晶蓝版本。
- 时间轴有旧时间控制、简易版足迹回顾中的时间组织方式和水晶时间轴三种表现，但它们没有被统一成一条产品路线。
- Figma 的“按时间与主题回顾”应该归到足迹下的简易回顾，当前页面命名还没有完全统一。
- 地图照片标记在 Figma 和网页中不是同一套视觉。
- Figma 有很多方向页和交接说明页，但最终主方案边界不够清楚。

一句话：现在像是一个已经能用的记忆地图产品，外面套了几代不同的设计语言。

## 6. 已经明确的设计决定

有明显依据的方向：

- 地图是 Web 的主背景和主要浏览场景。
- 照片是地图上的主要内容。
- UI 控件浮在地图上。
- 左侧栏不应该长期作为单功能主导航存在；代码还没完全移除，但方向已经明确。
- 时间轴属于足迹地图内部的核心辅助控件，不是独立主页面；所有时间范围依靠它控制。
- 按目前决定，时间轴非活跃时停靠在底部、露出一半，激活后向上展开。
- 不应该同时放一个重复的顶部时间筛选。
- 点击照片后地图继续保留。
- Web 偏沉浸式地图；软木板内容和卡片/时间组织方式合并成足迹下的简易回顾。

还没定：

- 时间轴展开后的准确高度。
- 地区控件是否始终显示。
- 地图照片标记最终使用圆形照片、卡片标记还是聚合标记。
- 简易版足迹回顾最终采用页面、抽屉还是其他承载方式，还没定。
- 水晶材质是否最终进入正式产品。

## 7. 水晶时间轴现在是什么状态（已归档）

本节内容保留为历史记录。水晶时间轴已从 Web 正式入口移除，相关组件、原型、样式和日期模型已归档到
`web/src/archive/crystal-timeline/`，不再作为正式产品路线。

### Figma 版本

Figma 版本有价值，适合统一尺寸、比例、年份刻度、轨道、焦点、把手和日期浮层。它是静态设计基准，不代表真实交互已经完成。

### 浏览器 Prototype

浏览器 Prototype 用真实地图测试拖动、日期变化、键盘和触摸。它比 Figma 更能说明实际使用感觉。

### 哪个版本最好

- 看外观：Figma 更适合。
- 看交互：浏览器 Prototype 更适合。
- 看正式产品完成度：两者都还不是正式版本。

### 已经确定的部分

- 横向年份轨道。
- 当前时间焦点和拖动把手。
- 日期浮层。
- 玻璃、蓝色高光、轻量透明材质。
- 底部半隐藏，激活后展开。

### 还没确定的部分

- 最终高度和露出比例。
- 展开、收起的具体动效。
- 是否和地图筛选、照片数量、标记变化实时连接。
- 移动端如何表现。
- 是否保留真实折射感，还是接受视觉近似。

### 正式使用还差什么

需要让水晶时间轴真正控制时间范围，淘汰旧时间控制，确认桌面和移动尺寸，并验收地图标记、数量、空结果、键盘和触摸同步。

## 8. 如果今天停止开发

这是基于当前检查的估计：

| 方面 | 完成度 | 原因 |
| --- | ---: | --- |
| 产品功能结构 | 70% | 解锁、记忆、地图、照片、编辑、同步主流程已经存在。 |
| 地图和照片主流程 | 70% | 地图查看、标记、点击详情、照片阅读比较完整。 |
| 主要页面设计 | 50% | 页面很多，但主方案还没有完全收束。 |
| 统一视觉风格 | 30% | 木质、纸张、金色、深色和水晶蓝仍然混在一起。 |
| 核心组件 | 55% | 有不少组件和 Figma 设计，但同一功能仍有多个版本。 |
| 动效和交互细节 | 25% | 水晶时间轴有实验级交互，正式页面还没有统一。 |
| Figma 交接完成度 | 55% | 页面和状态很多，但最终主方案边界不够清楚。 |

总体判断：功能完成度明显高于设计完成度。产品能运行，但还不像已经定稿的产品。

## 9. 接下来最应该做的三件事

### 1. 只确定一个足迹主页面和一个简易回顾入口

以 `Direction A / Footprints Overview` 作为足迹主页面，另定义一个足迹下的简易回顾入口。确定无长期左侧栏、地区控件、时间轴停靠位置、新增按钮和地图详情展开方式。其他页面从这两种形态延伸。

### 2. 统一时间轴

只保留一条时间控制路线：底部半隐藏、点击或拖动后展开，并实时影响地图标记和数量。旧时间控件和旧木质滑块淘汰；普通时间线的内容并入简易版足迹回顾，而不是继续作为独立功能。

### 3. 建立一套统一视觉规则

先统一地区控件、新增按钮、地图工具、照片标记、详情面板和时间轴。水晶视觉可以作为时间轴及相关浮层的局部语言，但不应突然把所有页面都变成玻璃风格。
