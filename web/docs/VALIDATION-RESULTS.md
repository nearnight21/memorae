# Web VMK V1 验证结果

> 验证日期：2026-08-10  
> 原型版本：`0.2.0`  
> 范围：本地离线 Web 原型，不含服务器同步、短信登录和正式地图体验

## 结论

Web 原型已经验证 VMK V1 的本地核心闭环：创建私密空间、加密真实文字和照片、锁定、
使用密码恢复，以及导出和导入密文包。浏览器持久层只保存密文；锁定后页面不再保留已
解密的记忆内容。

该结果说明协议可以在 Web 上工作，不代表服务器同步、跨端固定向量兼容或正式产品界面
已经完成。

## 自动化验证

运行：

```powershell
npm.cmd run verify
```

结果：

- TypeScript 检查通过。
- VMK 协议测试 8/8 通过。
- Vite 生产构建通过。

8 项协议测试覆盖：

1. 密码只用于解锁 VMK，导出信封不包含密码或明文钥匙。
2. 将密文 JSON 导入另一环境后，同一密码可以恢复并解密记忆。
3. 错误密码不能解开 VMK。
4. 同一条记忆重复加密会产生不同的 IV 和密文。
5. 篡改记忆密文会触发完整性校验失败。
6. V1 的照片共用 `PhotoKey`，但每次加密使用不同 IV。
7. 锁定后内存钥匙被清零，不能继续使用。
8. 导入会拒绝未知或不完整的密文包。

生产构建的默认入口约为 `253.92 kB`，gzip 后约为 `82.75 kB`。旧 Memories 界面使用
懒加载，不进入默认首屏；其独立 chunk 约为 `631.37 kB`，因此 Vite 仍会给出超过
500 kB 的提示，但不影响本次构建通过。

## 浏览器验证

桌面端和 390 px 宽度的移动端视口均完成以下检查：

- 创建私密空间成功。
- 加入真实文字、地点、标签和 PNG 图片后，可以正常解密显示。
- IndexedDB 中只写入密文记录和密文照片。
- 锁定后，测试标题从 DOM 中消失。
- 错误密码被拒绝，正确密码可以恢复原文字与照片。
- 导出操作显示成功。
- 移动端无横向溢出。
- 清理测试数据后，页面控制台无错误或警告。

浏览器自动化没有完整执行“清空本地数据后再选择文件导入”的文件选择流程；密文包结构、
跨环境解密和非法导入拒绝已经由自动化测试覆盖。正式发布前仍需做一次人工文件导入回归。

## 当前限制

- 只验证浏览器本地 IndexedDB，尚未接入正式后端。
- 照片当前整张读入内存后加密，30 MB 是原型限制，不代表正式上传方案。
- 正式 Memory 数据结构、版本迁移、缩略图、EXIF 处理和同步冲突尚未实现。
- Android 与 Web 的正式固定向量互通测试仍应在数据模型确定后补齐。
- `?legacy=1` 只是复用旧 Memories 界面的集成基础，不是正式地图产品。
