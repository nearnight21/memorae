# 所忆地图坐标工程约定

> 状态：2026-08-20 垂直切片审计结论。本阶段只明确边界，不迁移历史数据，也不修改 `MemoryV2`。

## 对外统一语义

`MapProvider`、`MemoryV2.lat/lng` 和 `/v1/location/reverse` 之间传递的都是“地图坐标”：

- 中国大陆：GCJ-02。
- 中国大陆之外：WGS-84。

`MemoryV2` 目前没有单独的坐标系字段。这是现有 Web 类型和地图实现已经采用的隐式不变量，移动端必须保持兼容，不能自行改成全局 WGS-84 或全局 GCJ-02。

## 各来源与处理方式

| 来源 | 原始坐标系 | 进入地图/记忆前的处理 |
| --- | --- | --- |
| Android 定位 | WGS-84 | 进入正式功能前调用所忆坐标转换链路；本切片不实现定位写入 |
| 照片 EXIF GPS | WGS-84 | 调用 `/v1/location/convert-gps`，再把返回坐标交给地图和 `MemoryV2` |
| 高德 Native 地图点击 | 高德地图坐标（境内 GCJ-02，海外按地图实际坐标） | 不再二次转换，直接用于 `/reverse` 和候选草稿 |
| Web Leaflet/高德地图点击 | 当前地图坐标 | 现有 Web 直接保存并调用 `/reverse`；经度另归一化到 `[-180, 180]` |
| `MemoryV2` 历史坐标 | 境内 GCJ-02、海外 WGS-84（隐式约定） | 原样显示；没有证据时不得批量转换 |

## 服务端接口约定

- `POST /v1/location/convert-gps`：接收原始 GPS/EXIF WGS-84，返回可直接落到当前地图上的坐标。
- `GET /v1/location/reverse`：接收已经可直接落图的“地图坐标”，不负责猜测或再次转换坐标系。
- `GET /v1/location/suggest`：返回可直接落图的候选坐标。
- 地点名称与行政层级最终仍由所忆服务端决定；高德 Native SDK 的本地地址结果不得直接写入 `MemoryV2`。

## 已确认的代码事实

- Web `MemoryV2` 类型注释明确规定境内 GCJ-02、海外 WGS-84。
- Web EXIF 解析得到 WGS-84，并在保存前调用 `/v1/location/convert-gps`。
- 服务端 `/reverse` 把输入坐标原样传给高德；海外行政信息不完整时，用同一坐标回退 BigDataCloud。
- 高德 Native 地图的点击与投影只属于地图渲染层，不承担地点字段生成。

## 尚未关闭的风险

当前 Web 会把所有 EXIF GPS（包括海外照片）交给高德坐标转换接口。仓库只有中国境内转换测试，尚无真实东京、巴黎、纽约转换结果证明海外坐标严格保持 WGS-84。

在真实接口验证前：

1. 不批量修改历史坐标。
2. 不在客户端额外执行第二次 WGS-84/GCJ-02 转换。
3. 海外 EXIF 测试必须同时记录原始坐标、`/convert-gps` 返回坐标和地图落点偏差。
4. 如果高德转换改变海外坐标，先汇报并在服务端按境内/海外明确分流，不在 Native View 内加入业务判断。
